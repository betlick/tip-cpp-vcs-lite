# Общие соглашения и интерфейсы

Соглашения приняты для совместной разработки. Форматы описывают будущую
реализацию; сейчас операции дискового хранения являются заглушками.

## Хранилище

| Путь относительно рабочего корня | Назначение |
| --- | --- |
| `.vcslite/state.json` | HEAD и последняя созданная версия |
| `.vcslite/commits/<id>/meta.json` | Данные коммита и полный перечень файлов |
| `.vcslite/commits/<id>/files/` | Содержимое файлов с исходными относительными путями |
| `.vcslite/tmp/` | Неполные снимки и временные данные |
| `.vcslite/backups/<backup-id>/files/` | Файлы резервной копии рабочего состояния |

Вся `.vcslite` исключается из обхода рабочих файлов. Каталоги коммитов
после публикации неизменяемы. Временные данные не видны в log. Размещение
каталога сборки и исполняемой программы пользователь выбирает вне рабочего
корня тестового репозитория.

## JSON и идентификаторы

Примеры: [state.example.json](storage/state.example.json) и
[commit.example.json](storage/commit.example.json).

- Пустое состояние: `{"head": null, "latest": null}`.
- ID - положительный последовательный номер, минимум шесть десятичных цифр:
  `000001`, `000002`, ..., `1000000`. Пропуски допустимы; повторное использование
  ID существующего коммита запрещено. Выбор следующего номера учитывает
  существующие опубликованные каталоги. Пользователь передаёт полный ID.
- У первого коммита `parentId` равен `null`; у остальных - ID последнего
  коммита на момент создания. Создание при HEAD, отличном от latest, запрещено.
- История сортируется по числовому номеру создания, а не по дате или строковому
  сравнению ID. Изменение системных часов не меняет порядок.
- Дата - строка UTC вида `2026-11-16T16:00:00Z`.
- Сообщение непустое и не состоит только из пробельных символов.
- JSON хранится в UTF-8. Пути в JSON относительные, разделитель `/`.
  В C++ используются `std::filesystem::path`; преобразования между UTF-8
  и представлением ОС выполняются на границе чтения и записи.
- Содержимое файлов не преобразуется, включая переводы строк.
- Размеры - неотрицательное целое число байтов; лимиты - 1000 файлов и
  100 000 000 байт на одно состояние. История и копии считаются отдельно.
- Названия полей и их типы соответствуют примерам. Отсутствие обязательного
  поля или неверный тип являются ошибкой.

Библиотека JSON будет выбрана и добавлена в сборку одним общим изменением
при реализации MetadataStore. Собственный парсер JSON не требуется.

## Операции Repository

| Метод | Результат и ответственность |
| --- | --- |
| `init()` | `true` - создан новый репозиторий, `false` - существующий сохранён |
| `commit(message)` | Полностью опубликованный `Commit`; обновление HEAD только после успеха |
| `log()` | `HistoryResult`: все коммиты от новых к старым и отдельный HEAD |
| `status()` | `StatusResult`: добавленные, изменённые, удалённые пути |
| `checkout(id, force)` | `CheckoutResult`: необязательный путь к сохранённой резервной копии |

Repository отвечает за порядок проверок, сохранение линейной истории,
генерацию ID, публикацию каталога версии и управление откатом. Все проверки,
которые можно выполнить до изменения данных, выполняются до записи.
`--force` меняет только правило о несохранённых изменениях.

## Операции FileStore

Корень рабочей папки задаётся конструктором. Методы не печатают сообщения.
Точные объявления находятся в `include/vcslite/file_store.hpp`.

| Метод | Контракт |
| --- | --- |
| `scan()` | Относительные пути и размеры рабочих файлов; исключает .vcslite, проверяет допустимые типы, пути и лимиты |
| `compare(snapshotFilesDirectory)` | Побайтовое сравнение с рабочим корнем; `nullopt` означает состояние до первого коммита |
| `saveSnapshot(destinationFilesDirectory, files)` | Сохранение рабочего набора в новый каталог внутри .vcslite/tmp; существующая история не меняется |
| `validateSnapshot(snapshotFilesDirectory, manifest)` | Проверка точного набора файлов, размеров, путей, коллизий имён и лимитов; отсутствие лишних и недостающих файлов |
| `backup()` | Полная копия рабочего набора внутри .vcslite/backups; возвращает каталог конкретной копии, содержащий files/ |
| `restore(snapshotFilesDirectory)` | Замена рабочего набора содержимым проверенного снимка; поддерживает переходы файла в каталог и обратно |
| `rollback(backupDirectory)` | Восстановление из backupDirectory/files/; служебное хранилище не удаляется |

Все переданные пути внутри хранилища проверяются перед записью. Ссылки и
перенаправляющие каталоги отклоняются. Операции не выходят за рабочий корень.
Манифест является полным перечнем файлов; сами байты сравниваются при status.
Контрольные суммы пока не предусмотрены, поэтому произвольная порча байтов
снимка без изменения размера не гарантированно обнаруживается.

После обычного успешного checkout Repository удаляет временную копию.
После checkout --force или неудачного rollback копия сохраняется. При ошибке
на этапе создания неполной копии рабочая папка остаётся без изменений.

## Операции MetadataStore

| Метод | Контракт |
| --- | --- |
| `readState()` | Проверенное состояние; некорректные JSON, ID или ссылки на отсутствующие версии отклоняются |
| `writeState(state)` | Запись временного файла и замена state.json; частичная запись не выдаётся за успех |
| `readCommit(id)` | Проверка ID перед построением пути, чтение метаданных и проверка совпадения сохранённого ID |
| `writeCommit(commit, temporaryCommitDirectory)` | Запись meta.json в новый временный каталог; не публикует коммит и не меняет HEAD |
| `readHistory()` | Все опубликованные метаданные в порядке от новых к старым |

FileStore проверяет физическое содержимое снимка; MetadataStore - формат
и значения метаданных. Между ними нет прямых вызовов; последовательностью
управляет Repository. Формат не обязан поддерживать перенос хранилища между ОС.

## Ошибки и вывод

Модули сообщают об ошибках исключениями `vcslite::Error` либо стандартными
исключениями файловой системы. `UsageError` используется для неверного
синтаксиса CLI. Только CLI выводит сообщения и определяет код завершения:

| Код | Значение |
| --- | --- |
| `0` | Успешная операция или справка |
| `1` | Ошибка выполнения операции |
| `2` | Ошибка синтаксиса аргументов |

Результаты идут в stdout, ошибки и предупреждение --force - в stderr.
Repository обязан выполнить требуемый откат до передачи ошибки в CLI.
Если откат не удался, итоговая ошибка содержит путь к резервной копии.
