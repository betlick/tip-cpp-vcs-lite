# VCS Lite

Учебный менеджер версий файлов на C++17 для macOS и Windows 10/11.
Сохраняет полные снимки выбранной папки; запланированы команды `init`,
`commit`, `log`, `status`, `checkout` и линейная история.

## Текущий этап

Подготовлены требования, общие типы, интерфейсы модулей, их связи и CMake.
Работают справка `--help` и разбор аргументов. Методы репозитория,
метаданных и файлового хранилища пока являются заглушками: они возвращают
явную ошибку и не создают или изменяют пользовательские файлы.

Полная реализация требований и выполнение приёмочных сценариев впереди.
Два подключённых к CTest теста проверяют запуск каркаса и обработку неизвестной
команды; они не подтверждают готовность функциональности VCS Lite.

## Каталоги и цели сборки

| Путь / цель | Назначение |
| --- | --- |
| `include/vcslite/` | Общие типы и публичные интерфейсы |
| `src/` | Точка входа и реализации модулей |
| `docs/` | Архитектура, соглашения и план работы |
| `docs/storage/` | Примеры JSON, не настоящие рабочие репозитории |
| `tests/` | Проверки через CTest |
| `vcslite_core` | Статическая библиотека Repository, MetadataStore, FileStore |
| `vcslite_cli` | Статическая библиотека интерфейса командной строки |
| `vcslite` | Исполняемый файл; в Windows имеет расширение `.exe` |

## Среда сборки

- CMake 3.20 или новее.
- macOS: Apple Clang из Xcode Command Line Tools; для установки инструментов
  используется `xcode-select --install`.
- Windows: Visual Studio с компонентами разработки классических приложений
  на C++ и поддержкой CMake. Команды выполняются в Developer PowerShell
  или Developer Command Prompt выбранной Visual Studio.
- Установленный CMake должен быть доступен по команде `cmake --version`.
- Каркас использует только стандартную библиотеку C++; внешние зависимости
  и загрузки при конфигурации CMake отсутствуют.

JSON-формат согласован. Библиотека для его обработки будет подключена при
реализации `MetadataStore`; сериализация сейчас не реализована.

## Сборка и запуск: macOS

Из корня исходного проекта:

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build
ctest --test-dir build --output-on-failure
./build/src/vcslite --help
```

## Сборка и запуск: Windows

Из корня исходного проекта в Developer PowerShell. Для генератора Visual Studio:

```powershell
cmake -S . -B build
cmake --build build --config Debug
ctest --test-dir build -C Debug --output-on-failure
.\build\src\Debug\vcslite.exe --help
```

Для генератора с одной конфигурацией исполняемый файл находится непосредственно
в `build/src/`, без промежуточного каталога `Debug`. Для смены компилятора или
генератора создаётся новый каталог сборки.

## Проверка установки каркаса

На обеих платформах:

```sh
cmake --install build --config Debug --prefix install
```

В результате программа устанавливается в `install/bin/`. Для запуска по имени
`vcslite` следует добавить абсолютный путь к этой папке в `PATH`. До этого можно
вызвать исполняемый файл по полному пути. Установка каркаса сейчас позволяет
проверить справку; полный цикл сохранения и восстановления станет доступен
после реализации.

Для удаления локальной установки удаляется созданная папка `install/`; если
её путь добавлялся в `PATH`, удаляется соответствующая запись. При собственной
установке через другой `--prefix` удаляется только установленный `vcslite`
или `vcslite.exe`, без удаления чужих файлов в общем каталоге.

## Правила работы с репозиторием

Общие заголовки и форматы меняются после обсуждения обоими участниками.
Каждый пишет свой модуль в отдельной ветке; перед объединением выполняются
сборка и доступные тесты. Персональные настройки IDE, результаты сборки,
установка и тестовые `.vcslite` не добавляются в Git.

После реализации проверять команды сохранения и восстановления следует в
отдельной тестовой папке, а исполняемый файл держать снаружи неё: исключения
файлов в VCS Lite первой версии не предусмотрены.
